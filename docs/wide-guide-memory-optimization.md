# 宽属性显存优化：后续工作与经验复用

记录时间：2026-11-11。当前基线是整合上游 v0.1.4 的 `eadcecc`。
本文件记录后续设计与验收方法，不表示优化已经实现或收益已经测得。

## 来源与当前行为

宽属性是上游既有功能，早于 v0.1.4；不是 ASI 分支新增的输入。
Fast 模式收到 `depth_of_field` 或 `responsivity`，且对应宽属性着色器
可用时，使用每像素 64 字节的属性记录，普通 Fast 属性为 48 字节。

当前遵循上游 v0.1.4：主中间缓冲采用 `Engine::fast_layout` 生命周期
复用布局，宽属性由 `attr_wide_` 按需独立分配。首次使用后保留复用，
随 sized 资源重建或引擎销毁释放，不是每帧分配。分配量约为最大分配
输入尺寸向上对齐到 32 后的像素数乘 64 字节，另加 64 字节余量。
1280×720 输入约 57.5 MiB，2560×1440 输入约 225 MiB。
这是独立缓冲大小，不是相对旧版的总显存净增量。

## 可复用的旧经验

旧实现保存在 `516ced2`（整合前 ASI 提交），重点查阅
`gpu/src/engine.cpp` 的 `resize`、`record_net` 宽属性分支，
`gpu/include/opennr_rr/engine.hpp` 的旧池化检查，以及
`asi/tests/test_asi_units.cpp` 的 B1 测试。历史证据见
`docs/test-evidence/rx9070xt-d3d12-validation-2026-11-08.log`。

- 旧方案扩容已有属性缓冲，并调整其他复用区域的地址，避免额外保留
  一整块宽属性缓冲。复用的是这个生命周期思路，不是照搬地址修正代码。
- 并行、无屏障阶段的资源可能同时存活，不能只按 CPU 录制顺序判断
  可重叠。旧 flow 区域重叠问题和反向测试应作为设计约束。
- 每个复用区必须记录最后读取、首次覆盖和中间的 GPU 同步。扩容或
  重建后必须更新全部视图，不能遗留指向旧分配的 GPU 地址。
- 保留普通/宽属性切换、跨帧历史、DRS、1080p/4K、有限值与重复
  输出检查。当前 20 帧重复序列可继续使用，但重复一致不能独自证明
  不存在确定性错误，必须加不复用的对照或独立布局审计。
- 旧 `has_flow_buffer_overlap` 与故意制造竞态的测试针对旧布局，
  不可直接套到新版；按实际并发存活集合重写。

## 新方案评估顺序

1. 固定相同输入、模式和最大输入尺寸，对比旧版、当前版的普通及宽
   属性场景。分开记录主 arena、宽属性缓冲、feature 总显存、进程
   显存与 GPU 时间，避免把独立缓冲大小当成净回退。
2. 基于 v0.1.4 的实际 dispatch/barrier 顺序建立生命周期表，包括
   宽属性生产/消费、flow 并行阶段、post 及跨帧历史。
3. 优先评估让 `fast_layout` 统一支持普通/宽属性两种布局：调整相应
   区域容量和偏移，并查找宽属性消费结束后可复用的区域。不能假设
   只把 48 改成 64 就安全，也不能挪用尚在使用的历史资源。
4. 比较首次出现宽输入时安全重建、预留容量、继续独立分配三种方案
   的显存、首帧开销与复杂度。重建必须遵守现有 GPU 完成/退休机制，
   不得销毁仍被录制或提交中的命令引用的内存。
5. 仅改变内存布局时，用当前独立分配版作相同着色器/权重的逐帧
   位精确对照。不要与旧版 LT_VO 算术差异混为一谈。覆盖 DOF、
   responsivity、两者同时存在、输入缺失和相关着色器缺失的回退。
6. 覆盖 D3D12、原生 Vulkan、DRS 增减、模式切换、交换输入类型、
   多实例与创建/销毁；记录显存峰值、稳态和重建延迟。验证有效的
   重叠负例应能被检查或测试捕获。
7. 只有在收益明确且没有输出/同步回退后，替代当前实现；将优化作为
   独立提交，保留当前分配路径作对照基线。

## 与 Mesa/ACO 层的关系

先在稳定的 ASI/上游引擎层评估布局，再在 Mesa/ACO 层重做验证。
新布局不应依赖某个编译器偶然产生的调度；改变着色器或编译宏后，
旧 ACO 编译记录与性能证据不能自动视为有效，需要重新生成或核验
输入哈希、编译配置和实际运行输出。
