1. **相对 RTX 5090 官方 NGX：画质高度相近下，4K 显存立省 `0.7 ~ 1.1 GB`（节省 `48% ~ 70%`，不到 5090 的一半）**
   OpenRR 通过按张量生命周期紧凑复用的单一显存池 `Engine::arena_` 分配中间激活缓冲（`Legacy` / `New` / `Fast` 三档显存占用差异 `< 0.5 MB`），在 4K UltraPerf / Perf / Qual 下分别仅占 **`487 / 586 / 791 MB`**（实机游戏 4K PBZ `2228x1253 -> 3840x2160` 实测 `684 MB`）；而 RTX 5090 官方 NGX `310.9.1.0` 在 4K 下即使仅按 `NVSDK_NGX_D3D12_GetStats` 内部口径也需 **`1,316 ~ 1,848 MiB`**（进程 DXGI 稳态 `1.68 ~ 2.14 GiB`，启用 DRS 峰值可达 `2.45 GiB`）。在保证 `New=1` 全 47 帧均值 `PSNR_01 = 49.20 dB`（`Reinhard = 54.29 dB`）的同时，对 12 GB / 16 GB 显存显卡开启 4K 光追 + 光线重建极为友好。
2. **相对官方 `OpenRR v0.1.7`**：
   在 Windows D3D12 Direct 路径下，双方共享同一套紧凑 `arena_` 布局，进程总显存增量基本持平（如 4K Quality 下分别为 `812.6 MB` vs `813.4 MB`，`v0.1.7plus` 略低约 `0.8 MB`；官方 `OpenNrRrRuntime.dll` 未导出 `feature` 细分统计）。而在**原生 Vulkan / Linux Wine `vkd3d-proton`（`RecordVk`）**路径下，`v0.1.7plus` 进一步将 Host 输入/输出缓冲改为按需紧凑分配，全资源直通时可比上游额外再省 **`60 ~ 130 MB`** 显存。
3. **`*` RTX 5090 测量口径说明**：
   RTX 5090 `03_timing_core` 在同一进程内按 `1080p_qual -> 1440p_qual -> 4k_qual -> 1080p_dlaa -> 4k_ultrap -> 4k_perf` 顺序串行执行，因此排在 `4k_qual` 之后的 `1080p_dlaa` 与 `4k_ultrap` 带有 CUDA / NGX 显存池保留（独立单跑 `1080p_dlaa` 约为 `176 ~ 365 MiB`）；而单调递增的前三档（`1080p_qual -> 1440p_qual -> 4k_qual`）以及释放重建后的 `4k_perf r2`（`1,316.1 MiB`）均为无历史污染的真实下界，证实 NVIDIA NGX 只要输出分辨率达到 4K 即会常驻 `1.32 ~ 1.71 GiB` 以上的内部显存池。

## 4. 综合推荐

- **日常默认推荐：`Mode = new`（`New=1`）**：`1440p Qual` **`4.79 ms`**、`4K Qual` **`10.50 ms`**、`4K Perf` **`6.67 ms`**，比官方 `v0.1.7` 快 **`6.0% .. 8.2%`**，47 帧均值画质高 **`3+ dB`**，且 4K 显存占用（`586 ~ 791 MB`）不到 RTX 5090 官方 NGX 的一半。
- **高帧率性能档：`Mode = fast`（`Fast=2`）**：`1080p Qual` **`2.64 ms`**（`3.03x` 5090）、`4K Qual` **`10.09 ms`**（`3.46x` 5090）、`4K UltraPerf` **`3.73 ms`**（`2.90x` 5090），比官方 `v0.1.7` 快 **`4.1% .. 9.2%`**，无 `non-finite` 异常，最深层跨帧复用使运动与极亮高光点会略有妥协。
- **逐位参考基准档：`Mode = legacy`（`Legacy=0`）**：保持与上游 FP16 主路径 `0-ULP` 位级一致，适合对照验证画质基线。
