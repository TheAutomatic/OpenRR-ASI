## 维度 3 — 同宿主同 SPIR-V ACO vs 驱动 LLPC（内部回退惩罚检验，非原版速度基线）

> [!IMPORTANT]
> **对照 ③ 口径纠偏声明**：Stage 8/9 中的“对照 ③（`samehost-llpc`）”把**专为离线 Mesa ACO 编写的 `mode-4` `saturatedConvertEXT` FP8 着色器**强行交给 Windows 驱动 LLPC 即时编译。驱动 LLPC 缺少硬件饱和转换折叠通道，会把 `qe4_pair32` 展开成软件 `clamp + class + cndmask` 指令海，导致对照 ③ 在 `New=1 @4K` 跑到 `13.089 ms`——比官方原版 `OpenRR v0.1.6` 用自家 FP16 为主着色器跑 LLPC（`11.381–11.386 ms`）**慢了 `+1.70 ms（+15.0%）`**。
> 因此，**对照 ③ 衡量的是“同 FP8 SPIR-V 在驱动 LLPC 下的回退惩罚”（论证这套魔改 FP8 着色器必须配发离线 `.nrp` 记录、不可裸退 LLPC），绝不能当作“比原版 `v0.1.6` 快 21.6%”的跨栈提速依据**。跨栈对标官方上游原版 `OpenRR v0.1.6` 的唯一有效速度依据为上文 **§2.1**（实测我方净胜 **`New=1` 提速 `+5.0%..+6.8%`、`Fast=2` 提速 `+6.6%..+7.9%` / `4K −0.81 ms`**）。

同 SPIR-V 内核位置对比：Stage 8 封板 `e745d71` 对照 ③（`New=1 @4K`）ACO `10588.3 µs` vs 同宿主 LLPC `12836.6 µs`（+21.23% 回退惩罚）；Stage 9 经 WP-D1a（enc_64 `−37.9 µs`）与第三轮解沙袋（`New=1` 22 核总和再降 `−59.1 µs` 至 `10525.7 µs`，`Fast=2` 再降 `−116.1 µs` 至 `10118.2 µs`）进一步拉大与 LLPC 回退态的落差。历史逆差三核定位：`post_f_lt` `1219.4 µs`（WGP 与 `LT_POST_STILL` 均已证伪）、`dec_dfn_160_256_fl_lt` `86.9 µs`（WGP/shared-cmat 均无收益）、`d3d_enc0_attr_f_lt` `854.7 µs`（Stage 8 `LT_ATTR_RCP=1` 已收窄至 2% 内）。
